# Installation and running

## PyTorch baseline

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[test]'
pytest -q
python scripts/train.py --device auto --epochs 2
python scripts/benchmark_pytorch.py --device cuda
```

Use `--device cpu` for the PyTorch benchmark on systems without CUDA.
MNIST is downloaded to `data/`. Checkpoint files and measurements are
written locally and excluded from Git to avoid fabricated/unportable data.

## Legacy Relay/AutoTVM CUDA build

The TVM script relies on **legacy Apache TVM v0.19.0**. Newer TVM
versions remove the Relay and AutoTVM APIs used in this older research.
Build TVM **from source with CUDA enabled** and verify these imports:

```bash
python -c "from tvm import relay, autotvm; print('legacy TVM OK')"
```

Upstream sources:
- https://github.com/apache/tvm/tree/v0.19.0
- https://tvm.apache.org/docs/install/from_source.html

Then run:

```bash
python scripts/tvm_autotvm.py --checkpoint checkpoints/lenet5.pt --batch-size 1 --tune --trials 50
```

Omit `--tune` to build without new tuning; if `results/autotvm_cuda.log`
exists the best saved configurations are applied. Legacy-version build
steps differ by CUDA toolkit, system compiler and Python environment.

## Standalone CUDA/C++ demonstration

On a Linux machine with an NVIDIA GPU and `nvcc` installed:

```bash
nvcc -O3 -std=c++14 cuda/conv2d_naive.cu -o conv2d_naive
./conv2d_naive
```

The standalone kernel is intentionally naive, not the original historical
TVM-generated kernel. It compares against a CPU correctness reference,
and reports timings for its own kernel launches only.

## Fair benchmarking

Both `benchmark_pytorch.py` and `tvm_autotvm.py` report **inference**
latency. Match GPU, batch size, dtype, checkpoint and environment when
comparing them. The original paper's 2.39x number is a **reported training
speedup**, not a measurement generated by these inference scripts.
